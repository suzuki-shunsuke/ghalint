# lockfile_is_required

The [workflow dependency lockfile](https://docs.github.com/en/enterprise-cloud@latest/actions/concepts/security/workflow-dependency-lockfiles) `.github/workflows/actions.lock` is required.

## Examples

:x: `.github/workflows/actions.lock` doesn't exist.

:o: `.github/workflows/actions.lock` exists.

You can generate the lockfile by `gh actions-lock`.

## Why?

[GitHub Actions workflow lockfiles are generally available](https://github.blog/changelog/2026-10-28-github-actions-workflow-lockfiles-are-generally-available/).
The lockfile locks actions a workflow uses to commits, including actions that the actions use.
Pinning an action to a full length commit SHA locks only the action itself, so the lockfile is better.

Actions in workflows should be managed by the lockfile. See [action_should_be_locked](015.md).

## Disable the lockfile support

If you don't use the lockfile, exclude this policy.

ghalint.yaml

```yaml
excludes:
  - policy_name: lockfile_is_required
```

Then the lockfile support is disabled entirely.

- [action_should_be_locked](015.md) is disabled
- [action_ref_should_be_full_length_commit_sha](008.md) validates all actions in workflows as before
