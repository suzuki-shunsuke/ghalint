# action_should_be_locked

Actions in workflows should be managed by the [workflow dependency lockfile](https://docs.github.com/en/enterprise-cloud@latest/actions/concepts/security/workflow-dependency-lockfiles).
Actions pinned by full length commit SHA aren't allowed.

This policy validates `jobs.<job_id>.steps[*].uses` in workflows.
The following actions are out of scope.

- Local actions such as `./.github/actions/foo`
- Docker images such as `docker://rhysd/actionlint:latest`. They are validated by [action_ref_should_be_full_length_commit_sha](008.md)
- Reusable workflows (`jobs.<job_id>.uses`). The lockfile doesn't pin them, so they are validated by [action_ref_should_be_full_length_commit_sha](008.md)
- Actions in action files such as `action.yaml`. They are validated by [action_ref_should_be_full_length_commit_sha](008.md). See [Action files](#action-files)

If the lockfile doesn't exist, [lockfile_is_required](014.md) fails instead.

## Examples

.github/workflows/actions.lock

```yaml
version: 'v0.0.3'
workflows:
  '.github/workflows/test.yaml':
    - 'actions/checkout@v6'
dependencies:
  'actions/checkout@v6':
    ref: 'v6'
    commit: '1af3b93b6815bc44a9784bd300feb67ff0d1eeb3'
    owner_id: 44036562
    repo_id: 197814629
```

.github/workflows/test.yaml

:x:

```yaml
steps:
  - uses: actions/setup-go@v6 # The lockfile doesn't manage it
  - uses: actions/checkout@1af3b93b6815bc44a9784bd300feb67ff0d1eeb3 # v6 # Pinned by commit SHA
```

:o:

```yaml
steps:
  - uses: actions/checkout@v6
```

## Why?

The lockfile locks actions to commits recursively, including actions that the actions use.
Pinning an action to a full length commit SHA locks only the action itself.
So actions should be managed by the lockfile rather than commit SHA.

## Action files

Actions in action files such as `action.yaml` should be pinned by full length commit SHA even if the lockfile is enabled.
The lockfile of a repository locks actions that its workflows use recursively, so actions in action files are locked too if callers of the action files use the lockfile.
But callers don't necessarily use the lockfile.
For callers not using the lockfile, pinning actions in action files by commit SHA is the only way to lock them.
Pinning by commit SHA doesn't harm callers using the lockfile.

If an action file is used only in the repository, you can exclude its actions from [action_ref_should_be_full_length_commit_sha](008.md).

## Exclude

You can exclude actions.
`action_name` is a [glob pattern](https://pkg.go.dev/path#Match).

ghalint.yaml

```yaml
excludes:
  - policy_name: action_should_be_locked
    action_name: suzuki-shunsuke/tfaction/*
```

`policy_name` and `action_name` are mandatory.

To disable the lockfile support entirely, exclude [lockfile_is_required](014.md).
